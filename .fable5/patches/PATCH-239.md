## Why (CTO, owner's screenshot + code read)
The AI post's **Edit** opens `components/ai/editors/AIContentEditModal.tsx` ("Edit AI Component"):
- Mind map and Flowchart show a raw **"Diagram code"** (Mermaid) textarea (`CodeDiagramEditor`, ~124).
- **Bug:** a mind map from Show options carries `tree` and is DRAWN from `tree` (PATCH-234), so editing the code
  changes nothing in the picture.
- An `infographic` (pyramid, cycle, …) falls through to "This content type has no editable fields."
Napkin edits by clicking the picture's own words; no code. This patch makes every AI picture editable through a
plain form; direct on-picture editing is the next step (PATCH-240, not in this patch).

## Design (all inside the existing modal; the save path is unchanged)
### 1. Mind map → a tree editor (no code)
- New `components/ai/editors/MindmapTreeEditor.tsx`: the centre topic (title of the map), then each **branch**
  as a row (text input, ↑/↓ reorder, × remove) with its **sub-points** indented under it (text input, ×), "+ Add
  sub-point" per branch and "+ Add branch". Limits: 8 branches, 6 sub-points each, labels ≤ 40 chars (the
  `OUTLINE_LIMITS`), at least 1 branch.
- Edits change `tree`; `code` is REGENERATED from the tree on every change (move the existing tree→Mermaid text
  builder in `outlineToVisuals.ts` into an exported `mindmapCodeFromTree(tree)` and reuse it, so stored `code`
  always matches the picture).
- A mind map WITHOUT `tree` (older Mermaid mind maps): new pure `lib/ai/mermaidMindmapParse.ts`
  `parseMindmapCode(code): MindmapTree | null` — Mermaid's indentation format: first non-empty line `mindmap`,
  then nodes by indentation depth; node text is unwrapped from `((…))`, `(…)`, `[…]`, `{{…}}`, `))…((`, `)…(` and
  surrounding quotes; an optional `id` prefix before the shape is dropped; `::icon(...)` and `:::class` lines are
  ignored; deeper than 3 levels is folded into level 3. Returns null when it cannot parse. When it parses, the
  modal edits it as a tree and saving stores `tree` + regenerated `code` (the picture moves to our renderer).
### 2. Flowchart → a steps editor (no code)
- New `lib/ai/mermaidFlowParse.ts` `parseFlowCode(code): { direction: 'LR'|'TD'; nodes: {id,label}[];
  edges: {from,to,label?}[] } | null` for the subset we generate and simple hand-written ones: `flowchart|graph`
  + direction; nodes `A`, `A[..]`, `A(..)`, `A("..")`, `A{..}`, `A((..))`; edges `-->`, `---`, `-.->`, `==>`,
  with optional `|label|`, chains `A --> B --> C`; `classDef`/`class`/`style`/`%%` lines ignored. Anything else
  (subgraph, click, etc.) → null.
- New `components/ai/editors/FlowStepsEditor.tsx`: **Steps** (text input per node, × remove, "+ Add step" which
  also connects the new step from the last one), **Connections** (from-select → to-select, optional label, ×,
  "+ Add connection"), **Direction** (Left to right / Top to bottom). Code regenerated by a new
  `flowCodeFromGraph(graph)` in `outlineToVisuals.ts` using `mermaidLabel` for every label and the palette
  `classDef`s (same style as today's Flow option).
### 3. Infographic → the same text form as Show options
- The modal renders the PATCH-237 `OutlineTextEditor` bound to `data.outline` (title, items, details, icons),
  plus a **Design** row (the designs that fit, from `suggestDesigns`, as small labelled buttons) and the PATCH-238
  **Colours** row. The live preview updates as you type. Save stores the edited `outline`, `template`, `theme`.
### 4. Code only as an escape hatch
- The Mermaid textarea moves into a closed **"Advanced: edit diagram code"** disclosure under the form, shown only
  for mind map/flowchart. When the code cannot be parsed into the form (null), the form is replaced by a short
  note "This diagram was written in code; edit it under Advanced." with the disclosure open.
- When a user edits code in Advanced on a `tree` mind map, `tree` is re-parsed from the code (or removed if it
  cannot be parsed) so the picture never ignores the user's edit (fixes the bug above).

## Tests
- `mermaidMindmapParse.test.ts`: our generated code round-trips (tree → code → tree equal); shapes and quotes
  unwrapped; ids dropped; icon/class lines ignored; depth folding; junk → null.
- `mermaidFlowParse.test.ts`: our generated flow code round-trips (graph → code → graph); chains; edge labels;
  each node shape; `graph TD`; subgraph → null.
- `flowCodeFromGraph`: hostile labels (`a"b]c{d}|e`) are neutralised (reuse the PATCH-233 assertions).
- Modal (`AIContentEditModal` tests): a tree mind map shows the tree editor and NO textarea by default; renaming a
  branch updates the preview text and the saved `tree` AND `code`; an old code-only mind map is converted to the
  tree editor; a flowchart shows Steps/Connections and saving regenerates `code`; an infographic shows the text form,
  design row and colours and saves `outline/template/theme`; an unparseable flowchart shows the Advanced note with
  the code; editing code under Advanced on a tree mind map changes the saved `tree`.
- **Mutations:** tree edit without regenerating `code` → the code-sync test fails; Advanced code edit not re-parsing
  `tree` → that test fails; `flowCodeFromGraph` without `mermaidLabel` → the hostile-label test fails.
